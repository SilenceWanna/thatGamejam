# 架构与迁移边界

## 数据流

`main` 读取并校验关卡 JSON → `BootScene` 依据清单加载资源 → `LevelScene` 装配角色、碰撞、收集物、出生点、音频与 UI。

场景中的拾取事件调用 `LevelProgress.collect`。集齐后只有回到出生点才能调用 `enterSpawnPoint` 进入排序。排序面板使用 `PhraseArrangement` 处理放入、移除、交换和答案比较，正确时通知场景完成关卡。

## 两类状态

- 玩法状态由 `LevelProgress` 管理：`exploring → returning → arranging → completed`；退出排序回到 `returning`。
- 界面状态由 `LevelScene` 管理：开始、游玩、排序、暂停、完成。暂停记录进入前的界面，物理与输入停止，继续后恢复原界面。

这两类状态分开是为了让暂停不改变收集或答题进度。排序时暂停物理，角色不会一边解题一边掉下平台。

## 输入与物理

`InputSource.sample()` 只返回 `moveAxis` 和 `jumpPressed`。`KeyboardInput` 处理 A/D/Space，并在失焦或页面隐藏时清空输入。新增手柄或移动端输入时，实现相同接口，在场景装配处替换或组合输入源；角色控制器不需要知道按钮名称。

Arcade Physics 固定 60 Hz，速度使用像素/秒。当前移动立即响应，无水平惯性；不支持二段跳。离台宽限 100 ms，跳跃输入缓冲 120 ms，均可从关卡配置调整为 0。角色的碰撞矩形独立于显示对象，基本图形和正式图片共用控制行为。

地面为实心静态碰撞体，三个平台为单向顶面碰撞体；下降且前一物理步脚底在平台上方时才允许落到平台。

## 音频与资源生命周期

`AudioService` 是声音播放的唯一入口。背景音循环、音效独立，整句与片段共享一个互斥试听通道。重复试听、关闭排序、暂停、重开都会清理旧片段，避免声音叠加。

Web Audio 使用预解码缓冲和 `AudioContext.currentTime` 排程，各段开始时间由前段实际时长累加。UI 在更新中读取音频时钟高亮当前槽位；渲染帧不会驱动音频衔接。初次点击开始时解锁声音。

Phaser 场景重开会清理世界、计时器、动画和显示对象；场景的 shutdown 额外解绑 window/document 输入监听、清理音频和排序面板。资源缓存使用“关卡 ID:资源名”，避免未来不同关卡同名文件相互覆盖。

## Unity 迁移

可以保留素材文件、片段 ID、关卡布局、正确顺序、数值参数和规则测试案例。`core` 中规则没有 Phaser 或浏览器依赖，方便用 C# 按相同行为重写。JSON 的左上角坐标可在 Unity 导入层转换成场景单位，并翻转 Y 轴。

需要重写 TypeScript 实现以及 Phaser 场景、输入适配、物理接入、UI、动画和音频适配。可分别映射到 Unity 的场景/组件、Input System、2D 碰撞、UI 和音频系统。Arcade Physics 与 Unity Physics 2D 不同，参数转换后仍需重新调校跳跃手感，不能保证直接复制数值就完全一致。

目前仅在输入、音频、资源和玩法规则处建立边界，未引入通用实体系统或大型引擎抽象。新增第二关可以复制内容目录并修改数据，再设置上一关的 `nextLevelId`。
